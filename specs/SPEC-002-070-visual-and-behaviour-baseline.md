## Problem

Owner (2026-10-24, viewer 3.3.5): "I like current state, add tests for how page looks and behaves
(playwright?)".

The suite has 658 Playwright tests that check behaviour and some geometry (SPEC-002-068 AC1,
SPEC-002-069 AC9), but nothing records how the page *looks*: a CSS change that moves, recolours,
hides or resizes something without breaking a specific assertion goes unnoticed. The owner wants
the current 3.3.5 state locked in.

Constraint: fonts differ between macOS (local) and Linux (CI); there is no Docker locally. Pixel
baselines must therefore come from one platform (CI Linux) and the cross-platform gate must not
depend on font rasterisation.

## Design

Two layers plus journeys, all in the existing `node --test` + Playwright library style (no
`@playwright/test`, no new npm dependencies).

### 1. Layout snapshots (cross-platform, always on)
- `tests/visual/scenes.js` defines named scenes: a deterministic setup (fixture board, persona,
  view, sidebar state, theme, language, reduced motion, frozen clock if the page shows times,
  draft text) plus a viewport.
- Scene set (minimum): topic view, All messages, room view (new topic), DM view, sidebar hidden,
  hover peek open, phone drawer open, Tools menu open, topic "..." menu open, destination popover
  open, Message options expanded, key approval notice with 3 pending keys, Signing review task,
  signing-board composer with unlock offer; each at 1280x800, and the composer scenes also at
  1280x460, 390x640 and 320x360; themes light, dark, dracula for topic view at 1280x800; Polish
  for topic view and key notice.
- For each scene record a JSON snapshot of a fixed list of landmark elements (header controls,
  #menu, #sideHide, .side, .feed, #title, #topicMenu, #composerTargetRow, #signingNotice, #cBody,
  #send, #composerTargetChange, #keyNotice, `.posting`, Tools items, ...): present, visible,
  bounding box, plus for each a small set of computed styles that encode the look (display,
  background-color, color, border-color, font-weight) and its accessible name/label text.
- Compare with tolerance: boxes within +-4px (width/height of text-bearing elements +-12% or 24px,
  whichever is larger, because of fonts); colours exact; visibility, presence and labels exact.
- Snapshots live in `tests/visual/layout/<scene>.json`, committed. `AFB_UPDATE_SNAPSHOTS=1`
  rewrites them; without it a missing snapshot fails (never auto-creates in CI).
- Runs in `npm test` on every platform.

### 2. Pixel screenshots (Linux baselines, CI gate)
- Same scenes; full-viewport PNG with animations disabled, caret hidden, and dynamic text
  (relative times, version strings if they change per release) masked or frozen.
- Baselines in `tests/visual/pixels/linux/<scene>.png`, committed.
- Comparison without new dependencies: load both PNGs into a canvas inside Chromium
  (`page.evaluate` with data URLs) and count differing pixels with a per-channel threshold;
  fail when more than 0.1% of pixels differ (configurable per scene). On failure write
  `actual`, `expected` and `diff` PNGs to `test-results/visual/` and upload them as a CI artifact.
- Runs when `process.platform === 'linux'` (CI) or `AFB_VISUAL_PIXELS=1`; on macOS it is skipped
  with an explicit skip reason (not silently passed).
- Baselines are generated by a `workflow_dispatch` input (`update_visual_baselines: true`) on
  test.yml that runs the generator on ubuntu and uploads the PNGs as an artifact; the parent
  commits them. The first baseline set is created this way in this spec.

### 3. Behaviour journeys
- `tests/journeys.test.js`: end-to-end user journeys of the current UI, each a sequence a person
  does, asserting visible outcomes (not internals):
  1. open board -> pick a topic in the sidebar -> highlight + #title follow -> type -> Post ->
     message appears in the feed and in the right folder;
  2. hide sidebar with #menu -> reload stays hidden -> hover peek -> switch topic twice inside the
     peek -> leave -> closed -> pin with the pin button -> shown after reload;
  3. phone 390x640: open drawer -> pick topic -> drawer closes -> compose and Post visible -> Post;
  4. reply from All messages -> chip row appears with the destination -> Post lands in that topic;
  5. key notice -> Review keys -> first pending selected -> paste correct fingerprint -> approve ->
     count drops -> notice disappears when 0 -> Not now persistence across reload;
  6. signing board composer: Sign this message -> status explains the missing step -> Post
     unsigned instead;
  7. shrink the window from 1280x800 to 320x360 with a draft and options open: field and Post
     stay visible at every step, draft kept.
- Reuse existing helpers; no duplication of existing per-feature tests beyond the journey glue.

### Non-vacuity
- A test-only CSS mutation (e.g. change the `.posting` border colour, move #send 20px, hide
  #sideHide) must make the layout snapshot comparison fail; a 1px-shift mutation must make the
  pixel comparison fail on Linux. Asserted inside the visual test file.

## Acceptance criteria

- [ ] AC1: layout snapshots for every scene in Design 1 are committed and pass on macOS locally and
  on Linux CI; a run without `AFB_UPDATE_SNAPSHOTS` never writes snapshot files.
- [ ] AC2: the three non-vacuity mutations fail the layout comparison with a readable message naming
  the scene, element and property.
- [ ] AC3: pixel baselines for every scene generated on CI Linux and committed; CI test job compares
  them and passes; on failure the diff artifact is uploaded; on macOS the pixel tests report as
  skipped with a reason.
- [ ] AC4: the 1px-shift mutation fails the pixel comparison (Linux).
- [ ] AC5: journeys 1-7 pass in Chromium; journeys 1, 2 (without peek) and 4 also in Firefox.
- [ ] AC6: two consecutive runs on the same machine produce identical layout snapshots and zero
  pixel difference (determinism), shown by running the generator twice in the AC3 workflow.
- [ ] AC7: docs: `docs/guides/TESTING.md` (or the existing testing doc) explains the layers, how to
  update baselines (`AFB_UPDATE_SNAPSHOTS=1` locally for layout; the workflow input for pixels),
  and that a baseline update must be reviewed like code. No viewer behaviour change; no release
  needed (test-only), CHANGELOG "Unreleased" note.
- [ ] AC8: total added time on CI <= 3 minutes.

No VoiceOver/screen-reader checks (owner policy).
